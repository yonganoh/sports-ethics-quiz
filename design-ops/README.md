이 폴더는 에이전트가 공통으로 읽는 규칙, 양식, 모듈 목록을 담습니다. 에이전트 정의는 `.claude/agents/`에 있습니다.

- 운영판(진척·간트·에이전트 편성): https://claude.ai/artifact/1Za9zBmz8w9KjWSfeq5UFH

- AI는 CAD 파일(.sldprt, STEP 등)을 열지 못합니다. 치수와 사양은 표, 텍스트, PDF, 스크린샷으로 받습니다.

## 문서 가독성 규칙 (모든 산출물)
사용자는 운영판 페이지의 **문서 탭**에서 이 문서들을 읽습니다. 탭은 상태 태그에 색을 입히고 목차와 태그 개수를 자동으로 보여 줍니다.
1. 제목 한 줄, 메타 표, **0장 한눈에 보기**(요약 3줄, 사용자 결정 상위 5개) 순서로 시작합니다.
2. 표는 열 5개 이하, 칸마다 한 문장입니다. 긴 설명은 표 아래 문단으로 뺍니다.
3. 상태 태그는 값 바로 뒤에 하나만 붙입니다. 하위 구분은 태그 안에 한 단어로 씁니다: `[가정: 기존]`, `[가정: 제안]`, `[가정: 일반]`, `[가정: 추정]`, `[미확인: 발췌 없음]`. 칸이 한 줄에 들어가게 짧게 씁니다.
4. 단위는 값과 함께 씁니다. 예: `195 mm [확정]`
5. 규격 시험 하중(IEC 61373 등)에는 안전율을 겹쳐 곱하지 않습니다. 사내 안전율 기준이 정해질 때까지 비교용으로만 `[가정: 제안]`으로 병기합니다.
6. 숫자 비교는 표만 쓰지 말고 **chart 블록**으로도 그립니다. 문서에 아래처럼 쓰면 막대 그래프로 보입니다(`target`은 목표선, `dir: up`이면 클수록 좋고 `down`이면 작을수록 좋음, 값 뒤 `| 메모`는 선택).
   ````
   ```chart
   title: 프레임 고유진동수 (목표 80 Hz 이상)
   unit: Hz
   target: 80
   dir: up
   2,030 스팬 | 44
   외팔 640 | 62 | 메모
   ```
   ````
7. 그림(개략도)은 에이전트가 만들지 않습니다. 메인 세션이 SVG로 만들어 운영판에 올리고, 문서에서는 `![그림 1 설명](img/파일명.svg)`로 참조합니다. 이 그림은 운영판 문서 탭에서만 보입니다.
8. 분류는 **MCT·TURNING**(절삭), **NCT·WELDING**(판금·절곡·용접), **READY-MADE**(구매품) 세 가지만 씁니다. 분류별로 표를 나눕니다.
9. 검증 모드에서 Drive 저장이 안 되면 `design-ops/output/`에 저장하고 사실을 보고합니다.

## 호출 방법
메인 대화에서 모듈 코드와 함께 지시하면 됩니다. 에이전트는 사용자에게 직접 질문할 수 없으므로,
필수 정보가 부족하면 **부족 정보 목록**만 돌려줍니다. 목록을 보고 정보를 채워 다시 지시하세요.

```
034 레일 검측장치 입력 조건서 작성해줘. (아래 사양 첨부)
034 설계 계획서 작성해줘.
```

## 함께 읽는 파일
- `modules.md`: 모듈 목록, 유형, 협력사와 진행 상태
- `프로젝트_공통요구.md`: 회의에서 확정된 공통 요구(운송 한계고 4,100 mm 등)와 Notion 참고 자료 위치
- `기본값_가정.md`: 사내 기준이 없을 때 쓰는 임시 기본값

## 공통 규칙 (모든 에이전트)
1. 필수 입력이 없으면 작업을 시작하지 않고 부족 정보 목록만 돌려줍니다. 추측으로 채우지 않습니다.
2. 모든 수치와 조건에 상태를 붙입니다: **[확정]** 사용자나 문서로 확인됨 / **[가정]** 일반값이나 제안값, 사용자 확인 필요 / **[미확인]** 아직 모름.
3. 계산과 검토에는 식과 가정값(근거)을 함께 적습니다. 결과는 참고용이며 최종 판단은 사용자가 합니다.
4. 산출물은 `design-ops/templates/`의 양식 구조로만 작성합니다.
5. 사내 기준이 없으므로 기본값은 `기본값_가정.md`를 쓰고 모두 [가정]으로 표시합니다.
6. 다른 모듈이나 이전 문서의 값을 현재 모듈에 옮길 때는 출처를 적습니다.

### 파일명과 상태
- 파일명: `[모듈코드]_[문서]_v01_YYYYMMDD.md` 예: `034_입력조건서_v01_20261109.md`
- 문서 상태: 작성중 → 검토요청 → 확정. 다음 단계 에이전트는 상태가 **확정**인 최신 버전만 근거로 삼습니다. 확정본이 없으면 그 사실을 알리고 최신 검토요청본을 [가정] 취급으로 사용합니다.
- 수정은 덮어쓰지 않고 버전을 올립니다(v01 → v02). 이전 버전은 사용자가 `99_이력`으로 옮깁니다.
- 상태를 확정으로 바꾸는 것은 사용자만 합니다. 에이전트는 항상 `작성중` 또는 `검토요청`으로 저장합니다.

## 검증 모드
이미 설계가 끝난 모듈로 에이전트와 양식을 시험할 때 "검증 모드"라고 지시합니다. 필수 정보가 부족해도 [미확인]으로 두고 끝까지 작성하며, 결과는 `99_이력`에 `_검증` 파일로 저장합니다. 실제 업무 폴더는 건드리지 않습니다.

## 외주 모듈
`modules.md`에서 유형이 `외주·프레임`인 모듈은 업체가 장비를 만들고 우리는 프레임을 설계합니다.
업체에서 3D 파일과 사양서를 받으며, 에이전트는 3D 파일을 열 수 없으므로 사용자가 아래 항목을 표로 옮겨 줘야 합니다.
외형 치수, 중량, 무게중심(있으면), 설치 홀·인터페이스 위치, 전원, 커넥터, 방열·진동·방수 조건, 파일 형식(STEP 등)과 수령 여부.
단계 이름은 입력·사양 = 외주 사양 확정, 설계 계획 = 외주 인터페이스(치수·전원·커넥터) 수신, 모델링·도면 = 프레임 설계로 읽습니다.
