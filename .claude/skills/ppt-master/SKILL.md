# PPT 제작 (PPT Master)

PPT를 만들 때 매번 같은 실수(바로 만들기, 글자 많음, 작은 글자, 넘침, 규칙 무시)를 반복하지 않도록 만든 작업 순서와 규칙이다. 사용자는 이 규칙을 이미 여러 번 말했고, 지켜지지 않으면 불편해한다. 이 스킬이 PPT 제작의 유일한 기준이다. 본 제작은 오픈소스 **PPT Master**로 한다.

## 0. 먼저 할 일

1. Drive 커넥터가 있으면 규칙 원문을 먼저 읽는다. 이 스킬과 다르면 **Drive가 이긴다**(규칙이 바뀌었을 수 있다).
   - `00_공통` 폴더(`CLAUDE.md`에 폴더 ID가 있다)에서 제목이 `00_START`로 시작하는 최신 파일 (PPT는 7장, 공통 규칙은 3장)
   - 같은 폴더에서 제목이 `작업규칙_PPT`로 시작하는 최신 파일 (예시 3가지 먼저, 회사 샘플 양식)
   - 표지 표기(이름·소속)와 회사 샘플 양식, 저장 폴더·파일 이름 규칙은 이 원문에 있다. 이 스킬에는 적지 않았다(공개 저장소).
2. 사용자의 그 자리 지시가 항상 우선이다. 우선순위: **사용자 지시 > 대시보드 작업 지침 > 00_START > 이 스킬**.
3. 커넥터가 없으면 이 스킬의 규칙으로 진행하고, 원문을 못 읽었다고 한 줄로 말한다.

## 1. 작업 순서 (건너뛰지 않는다)

1. **질문을 한 번에 모아서 묻는다.** 질문 도구로 선택형을 쓴다. 이미 아는 것은 묻지 않는다.
   - 용도와 받는 사람, 분량(핵심만 + 부록인지), 색·양식(회사 샘플을 따를지), 표지 표기, 사진을 쓸지
2. **예시 3가지를 그림으로 먼저 보여준다.** 같은 내용 한 장을 서로 다른 구성 3가지로 만들어 이미지로 보낸다. 말로 설명하지 않는다. 사용자가 고르면(섞어도 됨) 그때 본 제작한다.
   - 예시 슬라이드는 `pptxgenjs`(또는 `python-pptx`)로 만들어 LibreOffice로 PNG로 뽑아 한 장에 세로로 이어 붙이면 빠르다.
3. **선택을 확인한다.** 색, 분량, 표지 표기, 제외할 사진 같은 조건을 한 번 더 목록으로 확인받는다(질문 도구).
4. **본 제작은 PPT Master로 한다.** `references/ppt-master.md`를 읽고 그 절차대로 만든다(저장소 복제, 1·2단계 확인, 설계 명세, SVG 페이지, PPTX 내보내기). 아래 2~5장 규칙은 그대로 적용한다.
5. **출력 후 눈으로 확인한다.** PPTX → PDF → PNG로 뽑아 모든 슬라이드를 보고 글자 넘침, 겹침, 잘림, 사진 비율을 확인한다. 서버에는 맑은 고딕이 없어 대체 글꼴로 보이므로, 줄바꿈이 실제와 다를 수 있다고 사용자에게 알린다. 확인 방법은 `references/ppt-master.md` 6장.
6. **전달.** 파일을 `SendUserFile`로 보낸다. 저장 이름은 `#YYYYMMDD_이름_RevN.pptx`. Drive 저장을 요청받았는데 파일이 커넥터 한도(약 3.1MB)를 넘으면 억지로 우회하지 말고, 못 올렸다고 말한 뒤 선택지(사진 줄이기 / 나누기 / 직접 올리기)를 준다.

## 2. 표시 규칙 (모든 PPT)

| 항목 | 규칙 |
|---|---|
| 글꼴 | 한글은 **맑은 고딕**(PDF는 Noto Sans KR). 회사 샘플 양식이 지정되면 그 샘플의 글꼴을 따른다 |
| 글자 크기 | 제목 **28pt**, 본문 **13~16pt**(최소 13pt), 핵심 숫자 **26~32pt**. 사진 설명·출처는 12pt 이하 허용 |
| px 환산 | SVG 1280×720 기준 1px = 0.75pt. 제목 38px, 본문 20px(15pt), 설명 16px(12pt) |
| 글자 양 | 글은 적게. 한 쪽에 주제 하나, 항목당 2줄 이내. 본문 8~10쪽 + 부록 |
| 양식 | 기본은 **차콜/아이보리 + 구리색 포인트**, 카드·그림자 없이 얇은 선과 사진 중심. 업무 발표처럼 회사 샘플이 지정되면 Drive 규칙 원문의 그 샘플(색, 문체, 구성)을 따른다 |
| 표기 | 값에는 **[확정] [가정] [미확인]**을 붙인다. 계산 뒤에는 쉬운 말 한 줄 |
| 표지 | 작성자·소속 표기는 Drive 규칙 원문을 따른다. 가족·여행 자료는 이름을 넣을지 묻는다 |
| 금지 | 산출물에 **AI·Claude·도구 이름 표기 금지**. "문의 사항" 표현을 쓴다 |
| 공차 | 도면 공차는 숫자로만(H7 같은 문자 기호 금지) |
| 지시 없이 고치지 않기 | 이미 있는 도면·BOM·모델·Drive 파일은 지시 없이 바꾸지 않는다 |

## 3. 사진·자료 규칙 (여행·개인 자료)

- 사용자는 **실제 장소의 사진**을 원한다. 스톡 이미지나 AI 이미지로 실제 장소를 흉내 내지 않는다. 장소를 못 찾으면 비워 두거나 "예시"로 표시한다.
- 같은 장소가 아닌 사진에는 캡션에 **(예시)**, **(다른 시설)** 처럼 적는다.
- 자유 이용 사진은 출처 슬라이드에 촬영자·라이선스를 적는다. 사용자가 준 사진은 "사용자 제공, 출처 미확인, 개인 공유용"으로 적는다.
- 블로그·상품 페이지에서 가져온 사진은 슬라이드에 "개인 공유용, 외부 게시 금지"를 적는다.
- 사용자가 뺀 항목은 어떤 슬라이드에도 남기지 않는다. 마지막에 문구를 검색해 확인한다.
- 가격·맵코드·전화번호·영업시간은 검증하지 못했으면 **[미확인]**으로 표시하고 출발 전 확인하라고 적는다.
- 사진 구하기 요령과 사진 못 구할 때의 처리는 `references/photo-sourcing.md`.

## 4. 공개 저장소 주의

이 저장소는 공개 저장소다. 설계 값, 도면, 업체·사람 이름, 가족 여행 자료, 만든 PPT 파일을 저장소에 커밋하지 않는다. 산출물은 작업 폴더나 Drive에 두고 저장소에는 올리지 않는다. PPT Master 프로젝트 폴더도 복제본(`/home/user/hugohe3/ppt-master/projects/`) 안에만 둔다.

## 5. 자주 하는 실수 (이전에 실제로 있었다)

- 규칙을 읽지 않고 바로 만들었다 → 0번을 먼저 한다.
- 11~12pt 본문, 카드와 둥근 상자, 알록달록한 색 → 2번 표를 확인한다.
- 사진이 다른 장소인데 캡션이 없다 → 3번.
- 한 쪽에 글이 너무 많다 → 항목당 2줄, 나머지는 부록.
- 외부 서비스 키가 필요한 기능(AI 이미지 등)을 말만 하고 확인 없이 진행했다 → `references/ppt-master.md`의 이미지 절을 따른다.
- 파일이 커서 Drive 업로드가 막혔다 → 사진을 줄이거나 나누는 선택지를 먼저 준다.
- 받은 외부 저장소의 스크립트를 내용도 안 보고 실행했다 → 실행 전에 읽고, 막히면 사용자에게 묻는다.

## 파일

- `references/ppt-master.md` : PPT Master로 만드는 절차와 함정 (저장소 복제, 단계별 확인, 한국어 수치, 이미지, 검사)
- `references/photo-sourcing.md` : 실제 장소 사진 구하기
- `scripts/svg_helpers.py` : SVG 페이지를 스크립트로 만들 때 쓰는 도우미
